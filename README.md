# Payload LMS

`sourceplane/payload-lms` — a multi-tenant SaaS on Cloudflare Workers
and Supabase Postgres, run as an [Orun](https://github.com/sourceplane/orun)
component-native desired-state repo. Identity, organizations, projects, RBAC,
audit, metering, billing, webhooks and notifications are separate
bounded-context Workers behind one public edge API. The product is a learning
platform on Payload CMS: academies publish courses at its root, and its admin
is the staff console, where a Lumen account signs in and the account,
organization, notifications and billing pages live.

## Names

The repository is `sourceplane/payload-lms`. It was
`sourceplane/multi-tenant-saas-2` until 2026-10-30, and GitHub redirects the
old URLs. What is deployed keeps the original name, deliberately: the Workers
(`multi-tenant-saas-2-*`), the Orun project and its secrets
(`secret://…/multi-tenant-saas-2/…`), and the identity record
[`.rebrand/values.json`](.rebrand/values.json), which the rebrand reads as the
words a product replaces. Renaming any of those replaces a live resource, which
is a migration, not a rename.

## A baseline: products from this repository

This repository is also the **Multi-tenant LMS baseline**: a learning platform
is born from it — its own repository, Supabase projects, Workers and Payload
CMS, with a sample academy, live on stage and prod — by one artifact,
[`repo-blueprint.yaml`](repo-blueprint.yaml), run by `orun new`
([BOOTSTRAP.md](BOOTSTRAP.md) → [docs/phases/](docs/phases/README.md)). Eight
idempotent phases — scaffold, foundation, infrastructure, database, workers,
edge, console, docs — each land a verified pull request, and each is
selectable with `--phase <name>`. The console phase is this baseline's own: it
lands the learning platform (academies, courses, lessons, quizzes and learners
at its root, the staff console at `/admin`) and the console URL that redirects
into the admin. What the owner does afterwards is open the staff admin with a
setup token only they hold.

A product receives **product-only content**, branded with its own name: the
source, infrastructure and CI, its own README, AGENTS.md and operating guide.
None of the factory below ships, and nothing in a product says `lumen`: the
CMS names the platform `lumen` in its code (`lib/lumen/`, `lumenUserId`,
`LUMEN_API`), and the rebrand renames every form of it — paths included — into
the product's, so a Payload field and the column it maps to, a route and the
URLs that reach it, still agree.

## What is here

| Path | What it is |
|---|---|
| `apps/api-edge` | The one public HTTP entry point; reaches the workers over service bindings |
| `apps/*-worker` | Twelve bounded-context Workers — identity, membership, projects, policy, events, config, metering, billing, notifications, webhooks, integrations, admin. Never public |
| `apps/cms` | The product: the learning platform on Payload CMS (OpenNext on Workers). Academies and their catalogue at `/`, learners with their own accounts; the admin at `/admin` is the staff console, signed in with a Lumen account, with the account and billing pages calling the edge server to server |
| `apps/web-console-next` | The old console URL, now a redirect Worker: every path answers 308 to its place in the CMS |
| `packages/*` | Shared libraries: contracts, SDK, CLI, the database harness, the policy engine, the notifications client, the webhook verifier |
| `infra/terraform/*` | The data plane: Supabase projects, Hyperdrive, the edge's idempotency KV, the CMS's media bucket on R2, and the custom-domain component (parked until a domain is set) |
| `infra/db-migrate` | Database migrations — planned on pull requests, applied on merge |
| `tests/*` | Per-component contract and verifier suites |
| `intent.yaml` | The environments, the pinned composition catalog, and the Orun workspace this repository deploys into |

`stage` and `prod` are provisioned and deployed; `dev` is verify-only.

## How it deploys

Merges to `main` converge through Orun: `.github/workflows/ci.yml` runs
`orun plan --changed`, then one `orun run` lane per planned component. A pull
request plans and verifies; a push to `main` deploys `stage`, then `prod` once
`stage` has converged on the same commit. No pnpm, Wrangler or Terraform
command runs directly in CI.

The pipeline holds one credential, GitHub's own `GITHUB_TOKEN`. Cloudflare and
Supabase credentials are brokered per run from the workspace's connections;
nothing provider-shaped is stored in the repository or in GitHub.
