# cms — architecture

One Next.js 16 application (Payload 3.89.0) built by `@opennextjs/cloudflare`
into `.open-next/worker.js` plus `.open-next/assets`, deployed by the
`cloudflare-worker-turbo` composition. The wrangler config is rendered from
`wrangler.template.jsonc` at deploy time; it declares `main` and `assets`
itself, so the composition's `wrangler deploy` ships the whole build.

```
browser ──► multi-tenant-saas-2-cms-<env> (Worker)
              /admin            Payload admin (React, server components)
              /api/<collection> REST         ┐
              /api/graphql      GraphQL       ├─ payload ─► HYPERDRIVE_CMS ─► Supabase Postgres, schema cms
              /health           liveness + db ┘     │        (cache disabled)
              /api/media/file/* uploaded files      └──────► R2_MEDIA ─► <prefix>multi-tenant-saas-2-cms-media-<env>
              /setup            opens first-user setup (owner only)
```

## Bindings and secrets

| Name | Kind | From |
|---|---|---|
| `HYPERDRIVE_CMS` | Hyperdrive | `@@wiring(cloudflare-hyperdrive-cms/<env>:hyperdrive_id)@@` |
| `R2_MEDIA` | R2 bucket | `@@wiring(cloudflare-r2-cms/<env>:bucket_name)@@` |
| `ASSETS` | static assets | `.open-next/assets` |
| `ENVIRONMENT` | var | `dev` / `stage` / `prod` |
| `PAYLOAD_SECRET` | secret | `CMS_PAYLOAD_SECRET`, generated by terraform; pushed by `secrets-live` |
| `CMS_SETUP_TOKEN` | secret, optional | the owner's (runbook); absent = setup closed |

## Decisions that shape the code

- **No client-side pool on Workers** (`src/lib/request-scoped-pool.ts`).
  workerd binds a socket to the request that opened it; Payload keeps one pool
  per isolate, and pg-pool would hand one request a client another request
  opened, which hangs. The adapter gets a `pg` whose `Pool` opens a client per
  query or transaction and closes it on release. Hyperdrive pools to Postgres.
- **The schema is not the CMS's to change.** `push: false` at runtime; the
  tables come from `packages/db` migration 200, applied by db-migrate. Each
  collection change is a Payload migration in `payload-migrations/`, converted
  to idempotent SQL by `scripts/payload-migration-to-sql.mjs`.
- **Where the database comes from** (`src/lib/runtime.ts`). Inside the Worker:
  the binding. During `next build`, the payload CLI and local development:
  `DATABASE_URL`.
- **Media lives in R2, never on a disk** (`src/collections/Media.ts`,
  `src/lib/media-bucket.ts`). `@payloadcms/storage-r2` writes uploads to the
  `R2_MEDIA` binding and Payload serves them back through its access rules. On
  Workers the adapter is always on, and a Worker without the binding fails
  every upload naming it. Off Workers (local `next dev`, the CLI, `next build`)
  it is off and Payload's local disk stands in; with no prefix configured the
  table is the same either way. Uploads over 10 MiB are refused (413), not
  stored truncated: `abortOnLimit` is on.
- **Media belongs to the site or to one academy** (`src/collections/Media.ts`).
  `tenant` is optional: empty is the site's media, which editors manage; set,
  it is that academy's, which its instructors manage. Admins manage all of it
  and are the only ones who delete. `enforceMediaScope` checks the academy
  against what is written, so nobody moves a file out of their reach, and it
  runs before the storage adapter, so a refused upload stores nothing. Files
  are public by URL, like the cover and video URLs courses carry.
- **Closed by default** (`src/lib/setup-gate.ts`, `src/collections/Users.ts`,
  `src/app/setup/route.ts`). Creating the first account needs the owner's
  setup token; afterwards Payload refuses `first-register` itself.
- **Pinned versions.** Payload 3.89.0 hashes passwords with 25,000 PBKDF2
  iterations; 3.90.0 hard-codes 600,000, which workerd rejects. Next 16.3.3,
  React 19.2.6, OpenNext 1.20.1 and wrangler 4.116 are the combination Payload's
  own Cloudflare template ships with 3.89.0. `pg` and `pg-cloudflare` are
  direct dependencies and server externals: webpack would otherwise bundle
  pg-cloudflare's empty default export and Postgres connections fail in workerd.
- **Workers Paid.** About 3.8 MiB compressed with the learning app and the R2 adapter (Free allows 3 MiB), and Payload's first request in an
  isolate needs far more than Free's 10 ms of CPU.

## Out of scope here

Single sign-on with Lumen identity, serving content through `api-edge`, and
image derivatives: resizing, cropping and focal points need `sharp`, which does
not run on Workers, so files are stored and served as uploaded. Courses keep
`coverUrl` and lessons `video_url` as links: media does not replace them, and
video stays a link (10 MiB is too small for it).
